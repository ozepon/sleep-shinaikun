# セキュリティ検証記録

実施日：2026-10-21（日本時間）／対象：スリープしない君 1.0.1、同梱ソース、静的紹介サイト。

## 結論と配布可否

ZIP内の `.app` を配布する形式で構いません。ただし現在は **検証版** です。アドホック署名にHardened Runtimeを付けていますが、Developer ID署名・Appleの公証・チケットのstapleは未実施です。一般向けにそのまま配布して問題ない、または攻撃に対して安全だと保証する結果ではありません。

一般配布にはDeveloper ID署名と公証を行い、別のMacでダウンロード後の起動・管理者認証・オン／オフ・復旧を確認してください。[Appleの配布説明](https://developer.apple.com/developer-id/)を参照してください。署名用証明書・公証用アカウントは今回設定していません。

## 実施範囲

自分たちのコードと配布物だけを対象にした限定的な攻撃再現・レビューです。外部ntfyサーバー、Apple、Sites基盤、他人の端末への侵入・スキャン・負荷試験は行っていません。認証付き通知基盤の侵入試験や、第三者による独立監査ではありません。

## 攻撃ケースと結果

| ケース | 方法 | 確認結果 |
| --- | --- | --- |
| トピックへの入力攻撃 | 空、短すぎ、末尾LF、CRLF＋偽ヘッダー、`/../`、`?`、`#`、パーセントエンコード、シェル記号、引用符、バックスラッシュ、NUL、絵文字、101文字、100万文字の17入力 | 修正後の送信・QR URL・共通検証のすべてで拒否。各3判定、計51判定。シェル記号は文字列として渡すだけで、実行しない |
| 以前の末尾改行チェック | 以前の正規表現をそのまま評価 | 以前の送信側も末尾改行を拒否。改行による送信チェック突破は再現していない |
| 境界・送信データ | 16／100文字の正常入力、HTTPS固定宛先、POST、JSONキー、残量-1／101、Cookie・資格情報ストレージ | 正常値を受け付け、不正残量を拒否。端末名・パスワードを含まないキー構成を確認 |
| リダイレクトによる情報持ち出し | localhostの偽サーバーが307を返して別パスへ誘導。実際のURLSession通信を行う | 307の時点で停止。転送先 `/steal` へのリクエストは0件。外部には送っていない。全種類の転送コードを網羅した試験ではない |
| 配布物の改ざん | 一時ディレクトリにアプリをコピーし、実行ファイルの1バイトを反転 | 原本の署名検証は成功、改ざんコピーの署名検証は失敗。原本は変更しない。アドホック署名は第三者が再署名できるため、開発者の身元保証ではない |
| 管理者コマンドへの入力混入 | ソースを検査し、通知入力が管理者コマンド構築部に渡らないことを確認 | 固定の `/usr/bin/pmset -a disablesleep` とBoolから選ぶ0／1だけ。実際の権限昇格・管理者コマンドの攻撃実行はしていない |
| バッテリー条件 | 10%／9%、給電中、通知済み、14%／15% | 別途6判定を確認。低残量の重複抑制と再通知条件の限定的な確認 |

Swiftテストはリダイレクト試験を含め **65判定**。Pythonハーネスは転送先0件・原本署名・改ざん署名拒否・管理者コマンドの構成を追加確認します。実行結果は同梱 `Tests/results.txt` を参照してください。

## 見つかった点と修正

1. **QR生成側の入力検証が欠けていた。** 以前の送信側は検証していましたが、QR側は文字列をそのままURL末尾へ連結していました。`?`・`#`・長大入力などにより、送信先と異なる解釈やQR生成失敗につながる余地がありました。送信とQRの共通バリデータに統一し、16〜100バイトのASCII英数字・`_`・`-`だけを受け付けるように修正。無効な入力ではQRボタンも無効にしました。これによる任意ホストへの転送やコード実行を実証したという意味ではありません。
2. **通知のHTTPリダイレクトが標準動作のままだった。** 旧コードはURLSession.sharedを使い、リダイレクトを制限していませんでした。サーバー側の転送が起きたときの漏えい経路を減らすため、全リダイレクトを拒否する専用セッションに変更しました。Cookie・保存資格情報も使いません。TLS検証はOS標準のままです。外部ntfyサーバーが攻撃されたことを示すものではありません。
3. **通知オフ後の古い完了処理を無効化。** キャンセルと同時に世代IDを変更し、以前の通信の完了コールバックが状態を書き戻す可能性を抑えました。コードレビューによる対策で、タイミング競合を網羅した試験は未実施です。送信済みの通知を取り消すことはできません。
4. **配布物の実行保護を補強。** アドホック署名にHardened Runtimeを追加しました。公証の代わりにはなりません。

## 残るリスク・未検証

- **通知先の認証がない。** ntfyの公開トピックを使います。QR／トピックを知る人は通知の受信・なりすまし送信が可能です。これは今回の修正では解消していません。QRはiPhone1台に紐づく認証ではありません。
- トピックはUUIDで初期生成しますが編集可能です。推測しやすい文字列に変えると漏えいしやすくなります。トピックはUserDefaults、コピー操作後のクリップボード、iPhoneのブラウザ履歴などに残る可能性があります。暗号化された秘密情報保管ではありません。同じMacアカウントで動く悪意あるプロセスへの防御は想定していません。
- 通知内容・残量はntfyに渡り、外部サービスによる処理・保存や停止の影響を受けます。エンドツーエンド暗号化ではありません。
- スリープ防止はシステム全体に作用し、強制終了などでは設定が残る可能性があります。低残量通知は自動的にスリープ防止を解除する機能ではありません。
- iPhoneでの受信、ふたを閉じた状態での長時間稼働、他機種・Intel Mac、Gatekeeperのダウンロード後評価、macOS更新時の互換性は未確認です。
- サイトは静的HTML/CSS/JSです。入力フォーム、アカウント登録、通知トピック保存、管理者コマンド実行機能はありません。紹介サイトのソース確認にとどまり、Sitesホスティング基盤の侵入試験は行っていません。

**一般配布に向けた残作業：** Developer ID署名・公証、別MacとiPhoneでの実機試験。QR漏えい時の不正受信・送信を防ぐ必要がある製品として配布する場合は、認証と失効機能のある通知基盤への変更も必要です。

## 再現方法

Xcode Command Line ToolsとPython 3のあるMacで実行してください。localhostの18766番ポートを使い、外部サービスへの通信や管理者コマンドの実行はしません。

```bash
./build.sh
xcrun swiftc Sources/NotificationSecurity.swift Tests/main.swift -module-cache-path build/module-cache -o build/security-tests
python3 Tests/attack_harness.py
"build/スリープしない君.app/Contents/MacOS/LidAwake" --self-test
"build/スリープしない君.app/Contents/MacOS/LidAwake" --qr-self-test
```

配布ZIPのSHA-256はサイトの `SHA256SUMS.txt` に記録します。ハッシュはダウンロードの一致確認用で、同じサイト上のハッシュとファイルが同時に改ざんされる攻撃を防ぐものではありません。
