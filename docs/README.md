# スリープしない君

MacBookのスリープ防止をオン・オフするメニューバーアプリ。バッテリーが10%未満になると、インターネット経由でiPhoneへ通知できます。QRからntfyのWebアプリを登録する方式です（iOS 16.4以降）。

## 動作環境と現在の状態

- macOS 13以降向けのSwift / SwiftUIアプリ。ビルド済みファイルはApple Silicon用です。
- ビルドスクリプトは、実行したMacのCPU向けに生成します。
- Hardened Runtimeを有効にしたアドホック署名です。Developer ID署名・Appleの公証は未実施です。他のMacで通常の配布アプリと同じように開けることは保証していません。公開サイトに置くダウンロードは検証用です。
- ビルド、署名検証、設定読み取り、バッテリー判定の確認を実施。ふたを閉じた実機での継続稼働とiPhoneへの到達確認は未実施です。

## 起動とスリープ防止の使い方

1. `build/スリープしない君.app` を開きます。Dockではなくメニューバーに月／太陽のアイコンが表示されます。
2. アイコンをクリックして設定を開きます。
3. 「スリープ防止」をオンにし、macOSの管理者認証を許可します。
4. オンでは太陽と「ON」、オフでは月が表示されます。
5. 終わったらオフに戻します。オフにする際も管理者認証が必要です。

起動だけでは電源設定を変えません。スイッチは保存済みの希望値ではなく、実際のmacOS設定を表示します。認証キャンセルや失敗の場合は読み直し、エラーを表示します。

**オンにすると、ふたを閉じたときだけでなく、バッテリー使用中もシステム全体のスリープが無効になります。** 発熱・電池消費が増える場合があります。通気のよい場所で使用し、バッグに収納する前にオフにしてください。

## iPhoneへの低残量通知

1. Macでこのサイトからアプリをダウンロードし、ZIPを展開します。
2. 「スリープしない君.app」をダブルクリックします。現在は未公証の検証版のため、macOSに起動を制限される場合があります。
3. Mac画面いちばん上のメニューバー（時計などがある場所）で、月／太陽のアイコンをクリックします。
4. 開いた設定画面の「iPhoneに低残量を通知」をオンにします。「スリープ防止」とは別のスイッチです。
5. 通知をオンにすると同じ画面にQRが自動表示されます。初回の「通知停止中」は正常です。
6. iPhoneのカメラでQRを読み、リンクをSafariまたはChromeで開きます。この紹介サイトではなく、ntfy.shの通知受信ページが開きます。
7. iPhoneのブラウザの共有ボタンから「ホーム画面に追加」→「追加」を選びます。
8. iPhoneのホーム画面に戻り、追加された「ntfy」アイコンをタップします。通知の許可を求められたら「許可」を選びます。ページに通知を有効にする操作があれば実行してください。
9. Macのトピックが購読一覧にあることを確認します。なければ「Subscribe」で、MacのQR画面に表示されたトピックを登録します。
10. Macのアプリで「テスト通知」を押し、iPhoneに通知が表示されることを確認します。
11. 届いたらMacの「iPhoneで届いたことを確認した（7日間有効にする）」を押します。届かない場合は押さず、iPhoneの通知設定・集中モード・接続を確認します。

**QRを読み取るだけでは通知は有効になりません。** ホーム画面への追加・通知の許可・トピックの購読が必要です。iPhoneのネイティブntfyアプリへの自動登録用リンクではありません。現在のiOS版ntfyは自動登録用ディープリンクを提供していないため、Webアプリを使います。[公式PWA設定説明](https://docs.ntfy.sh/subscribe/pwa/)と[Web通知の条件](https://docs.ntfy.sh/subscribe/web/)も参照してください。

ntfyのWeb通知は、1週間以上アプリを開かないと休止されます。定期的にホーム画面のntfyを開いてください。既存のiPhone用ntfyアプリを使う場合は、サーバー `https://ntfy.sh` と同じトピックを手動で購読することもできます。

このQRは端末を識別するペアリングではありません。同じQR／トピックを登録した端末すべてが受信でき、iPhone1台に限定する認証機能はありません。
両端にインターネット接続が必要です。近くに置く必要や同じWi-Fiにつなぐ必要はありません。Macアプリを終了している間やMacがスリープ中は監視・送信できません。スリープ防止と通知は独立した設定です。

### 通知の条件

- 30秒ごとに内蔵バッテリーを読みます。
- バッテリー駆動中、整数の残量表示が **10%未満（9%以下）** なら送信します。10%ちょうどでは送りません。
- 通知をオンにした時点ですでに条件を満たしていれば送信対象になります。
- サービスが送信成功を返したら、その低残量期間の通知は一度だけです。状態はMac内に保存し、アプリを再起動しても重複を抑えます。
- 15%以上になったことを監視中に検出すると、次の低残量通知を有効にします。
- 失敗した低残量通知は5分、10分、20分、40分、以後60分の間隔で再試行します。再試行時も低残量・バッテリー駆動の条件を確認します。
- 「テスト通知」は残量に関係なく送信し、自動通知の送信済み状態は変えません。
- 送信完了はntfyサーバーの受け付けを意味します。iPhoneへの到達保証ではありません。iPhoneの通知設定、集中モード、ネットワーク、サービスの制限などで遅延・不達が起きる場合があります。

### 通知データとプライバシー

初回にUUIDを含む推測しにくいトピックを生成します。トピックはパスワードではなく、公開サービス上の宛先です。**知っている人は受信・送信できるため、QR、スクリーンショットや公開READMEに自分のトピックを載せないでください。** アカウント認証やトピックのアクセス制限はこのバージョンでは扱いません。

通知を有効にした場合とテスト送信時だけ、HTTPSで `https://ntfy.sh` にトピック・アプリ名・通知文・バッテリー残量（自動通知のみ）・優先度・タグを送ります。Mac名やApple Account、管理者パスワードは送りません。配信にはntfyとiPhoneのプッシュ通知の仕組みを使用します。外部サービスには送信元IPなどの通信情報が渡ります。

トピック、通知のオン・オフ、送信済み状態を `UserDefaults`（`local.lidawake.app`）に保存します。サイトから利用者の通知先を登録したり、実際の電源設定を操作したりすることはありません。

## 内部でやっている処理

### 電源設定

SwiftUIのスイッチ → `NSAppleScript`の管理者認証 → 固定された次のコマンドを実行 → `pmset -g`で読み直し、という流れです。管理者パスワードはmacOSが扱い、アプリには保存しません。

| 操作 | 実行するコマンド |
| --- | --- |
| オン | `/usr/bin/pmset -a disablesleep 1` |
| オフ | `/usr/bin/pmset -a disablesleep 0` |
| 状態確認（5秒ごと・設定画面を開くとき・変更後） | `/usr/bin/pmset -g` |

`-a` は電源アダプタとバッテリーの両方を対象にします。出力の `SleepDisabled` が1ならオン、0ならオフです。読み取れなければ切り替えを無効にします。

通常のアイドルスリープ防止APIだけでは、ふたを閉じた際のスリープを防げません。このアプリは `disablesleep` を使用します。[Appleの公開ソース](https://github.com/apple-oss-distributions/PowerManagement/blob/main/pmset/pmset.m)に存在しますが、一般向けマニュアルには載っていない設定です。将来のmacOSでの互換性は保証できません。

### バッテリーと通知

`IOKit.ps` の `IOPSCopyPowerSourcesInfo` / `IOPSCopyPowerSourcesList` / `IOPSGetPowerSourceDescription` で内蔵バッテリーの現在容量・最大容量・電源種別を取得します。`現在容量 × 100 ÷ 最大容量` の整数値で判定します。条件成立時、`URLSession`でntfyの[JSON送信API](https://docs.ntfy.sh/publish/)へPOSTします。常駐デーモンやBluetooth通信は使いません。

### 終了時

オンのまま終了しようとすると「オフにして終了」「キャンセル」「オンのまま終了」を表示します。「オフにして終了」では、オフへの変更成功を確認してから終了します。強制終了や「オンのまま終了」ではmacOS側の設定が残る場合があります。

## 設定が戻らないとき

アプリを開いてオフにするか、ターミナルで次を実行してください。管理者認証が必要です。

```bash
sudo pmset -a disablesleep 0
```

確認は `pmset -g` で行えます。`SleepDisabled 0` ならスリープ防止はオフです。

## ソースとビルド

```bash
cd LidAwake
./build.sh
```

Xcode Command Line Toolsが必要です。生成先は `build/スリープしない君.app` です。

| ファイル | 役割 |
| --- | --- |
| `Sources/main.swift` | メニューバーUI、電源設定変更、状態確認、終了処理 |
| `Sources/BatteryNotifier.swift` | バッテリー監視、送信条件、ntfy送信、通知設定UI |
| `Sources/NotificationSecurity.swift` | 共通入力検証・固定宛先・リダイレクト拒否 |
| `Sources/PhoneSetup.swift` | Core ImageによるQR生成、iPhoneの登録手順 |
| `build.sh` | Swiftコンパイル、Info.plist生成、アドホック署名 |
| `site/dist/` | 配布用サイトとダウンロード資材 |

読み取りのみの確認と、外部送信しない通知判定チェック：

```bash
"build/スリープしない君.app/Contents/MacOS/LidAwake" --check
"build/スリープしない君.app/Contents/MacOS/LidAwake" --battery-check
"build/スリープしない君.app/Contents/MacOS/LidAwake" --self-test
```

QRはCore ImageでMac内に生成します。内容は `https://ntfy.sh/<トピック>` のHTTPS URLのみです。QR作成用の外部サービスには送信しません。

## セキュリティ検証と配布

現在の配布物は1.0.2の未公証の検証版です。攻撃ケース、修正内容、未解消のリスク、再現手順は [SECURITY.md](SECURITY.md) を参照してください。通知先トピックを知る第三者の受信・送信は防げません。一般向け配布にはDeveloper ID署名・公証と別Macでの実機確認が必要です。

## 7日間の受信確認期限（1.0.2）

初回の自動通知は停止しています。テスト送信成功後、iPhoneで通知を確認し、Macの確認ボタンを押すと7日間（168時間）有効になります。期限切れ時はメニューバーに⚠︎、設定画面にオレンジの「通知停止中」を表示し、自動送信を停止します。スリープ防止は変更しません。

iPhoneのホーム画面からntfyを開き、テスト通知を受信して、Macで再確認すると7日間再開します。送信成功だけでは延長しません。通知先トピック変更時も再確認が必要です。期限は再起動後も保存します。時計が確認日時より前になった場合も再確認します。

MacはiPhoneの通知許可や実際の不達を検出できません。表示は受信確認期限に基づきます。有効期間中の到達保証ではありません。通知を受信しただけ、Macアプリを開いただけでは期限は延びません。

## 1.0.6：切替だけの限定許可（任意）

有料のApple Developer Programや常駐rootヘルパーを使わず、macOSのsudoersに現在のユーザー専用の限定許可を追加する方式です。初期状態は無効です。アプリの「切替の認証を省略する…」を選び、説明を確認し、管理者認証したときだけ設定します。

許可するのは `/usr/bin/pmset -a disablesleep 0` と `/usr/bin/pmset -a disablesleep 1` の2コマンドのみです。ワイルドカード、任意のシェル、他のpmset引数を許可する規則は追加しません。通常の切替はsudoを非対話モードで呼び出し、OSに引数の一致を検証させます。

**アプリ固有の許可ではありません。同じMacユーザーで実行される他のプロセスも、この2コマンドを実行できます。** これにより悪意ある同一ユーザーのプロセスがスリープを妨げたり、逆にスリープ防止を解除したりする可能性があります。一般的なroot権限を渡す設定ではありませんが、リスクはゼロではありません。トピックや外部の通知でコマンドを指定する機能はありません。

設定先は `/private/etc/sudoers.d/sleep-shinaikun-<数値UID>` です。所有者root・権限0440で保存します。メインのsudoersは書き換えません。既存sudoersで標準のsudoers.d読み込みが有効で、ディレクトリがroot所有・755である場合だけ設定を進めます。既存ルール・追加ルールをvisudoで構文確認し、追加後に全体の検査が失敗したら追加ファイルを除去します。既存の同名ファイルが想定と違う内容だったりシンボリックリンクだったりする場合は変更を拒否します。

解除は先にスリープ防止をオフにしてから「認証省略を解除…」を押し、管理者認証します。想定する内容と一致する専用ファイルだけ削除します。**アプリをゴミ箱に入れる前に解除してください。アプリの削除だけでは許可は消えません。** 再インストール・アップデート時は同じUIDの許可が残ります。

インストール／解除の実行・その後のパスワード不要切替はこの開発環境では未実施です。実際のsudo設定を変更しない31項目の検査（規則の限定、visudo構文、シェル構文、AppleScriptコンパイル等）を実施しました。許可が効かない場合は、勝手に許可を拡大せずエラーを表示します。通常認証のまま使うこともできます。

確認用コマンド（コンパイルと一時ファイル検査だけで、sudo設定は変更しません）：

```bash
xcrun swiftc Sources/LimitedPermission.swift Tests/Permission/main.swift -module-cache-path build/module-cache -framework Cocoa -o build/permission-tests
build/permission-tests
```
