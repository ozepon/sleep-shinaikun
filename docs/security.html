限定したローカル試験を通過しましたが、安全性の保証や独立した侵入試験ではありません。一般配布に必要なDeveloper ID署名・Appleの公証は未実施です。QR／トピックを知る人による通知の受信・なりすまし送信も、現在の方式では防げません。

1.0.2の変更

7日の受信確認期限を追加。初回・直後・1秒前・ちょうど・期限後・時計巻き戻しの6判定を追加し、現在のSwift検証は71判定です。以下の1.0.1の記録は履歴です。iPhoneでの受信は未確認です。

今回の検証範囲

対象は自分たちのSwiftコード、ビルドしたアプリ、配布ZIP、静的サイト。外部のntfy・Apple・Sites基盤や、第三者の端末への攻撃・スキャン・負荷試験は行っていません。偽サーバーはlocalhost上に立て、アプリの改ざんは一時コピーだけに行いました。

1.0.1で修正したこと

  1. QRと送信の入力検証を統一。以前のQR生成は未検証の文字列をURLに連結していました。現在は16〜100バイトのASCII英数字・「_」「-」だけを許可し、不正入力ではQRを表示しません。
  2. HTTPのリダイレクトを禁止。通知データを転送先へ送らないように専用セッションへ変更。Cookieと保存資格情報も使いません。TLS検証はOS標準のままです。
  3. 通知オフ後の古い処理を無効化。キャンセルと同時に世代IDを変え、過去の完了処理による状態更新を防ぐ対策を追加。タイミング競合の網羅試験は未実施です。
  4. Hardened Runtimeを追加。アドホック署名の実行保護を補強しました。Developer ID署名や公証の代わりにはなりません。

残るリスク

  • QR／トピックを知る人は、受信も送信もできます。iPhone1台に限定した認証や失効の仕組みはありません。機密用途向けの通知基盤ではありません。
  • トピックはUserDefaults、クリップボード、iPhoneのブラウザ履歴などに残る場合があります。同じMacアカウントの悪意あるプロセスへの防御は想定していません。
  • 通知は外部サービスntfyへ送られます。エンドツーエンド暗号化ではなく、遅延・不達・サービス停止の影響を受けます。
  • スリープ防止はシステム全体へ作用し、強制終了では設定が残る場合があります。残量が低くなっても自動解除はしません。
  • iPhoneへの実配信、ふたを閉じた長時間稼働、他機種・Intel Mac、ダウンロード後のGatekeeper評価は未検証です。

一般配布までに必要なこと

Developer ID署名・Appleの公証・チケットのstaple、別のMacでの起動と管理者認証、オン／オフ・復旧、iPhone受信の実機確認が必要です。通知の不正受信・なりすましを防ぐ製品として配布する場合は、認証と失効を持つ通知基盤への変更も必要です。

検証を再現する

ソースを展開し、Xcode Command Line ToolsとPython 3のあるMacで実行します。localhostの18766番ポートを使います。実際の管理者コマンドや外部サービスへの送信は行いません。

./build.sh
xcrun swiftc Sources/NotificationSecurity.swift Tests/main.swift -module-cache-path build/module-cache -o build/security-tests
python3 Tests/attack_harness.py
"build/スリープしない君.app/Contents/MacOS/LidAwake" --self-test
"build/スリープしない君.app/Contents/MacOS/LidAwake" --qr-self-test

配布ファイルの一致確認には SHA-256一覧 を利用できます。同じサイトのZIPとハッシュが同時に書き換えられた場合を防ぐものではありません。
